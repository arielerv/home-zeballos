## Required implementation dependencies and boundaries

| Capability | Required implementation choice | Constraints |
|---|---|---|
| Web 2D | `react-konva` + `konva` over the existing React stack | Canvas is only the editing surface; snapping, dimension semantics, undo and BIM actions are application logic and require tests. |
| Parametric model / evidence | Existing `@t3-designer/architecture-model` (Zod) + deterministic `@t3-designer/architecture-engine` + `@t3-designer/architecture-validation` | Canonical source is renderer-independent; generated meshes are outputs only. |
| Robust planar checks | `shapely` in the isolated Python validation/import adapters; retain deterministic TypeScript validation in the main app | Pin and run fixtures in CI; record precision/units. |
| IFC | `ifcopenshell` isolated import/export adapter | IFC schema version, mapping, licensing and round-trip fixture must be explicit; no frontend dependency. |
| DXF | `ezdxf` isolated adapter | Test units, layers, blocks, dimensions and round-trip against checked-in fixtures. |
| DWG | Configured ODA File Converter / approved DWG SDK adapter | Separate installed tool/license and real DWG fixtures are mandatory. DXF does not imply DWG support. Missing tool blocks release. |
| glTF/GLB + OBJ | Existing `three` exporters and Blender's glTF exporter | Export from canonical snapshot. GLB-only legacy model is not BIM export support. |
| Prompt operations | Provider-neutral server boundary plus Zod operation schema; provider not selected yet | Do not add API credentials to browser; no arbitrary generated code; user reviews before apply. |
| 2D/3D geometry | Existing `packages/geometry`, Three.js renderer, Blender background/MCP for inspection | Neither renderer is the source of architectural truth. Blender MCP is unavailable in the current session; local background Blender is not equivalent to MCP feedback. |
| Solar | Existing solar position/daylight engine, parameterized for site/timezone | Solar UI remains required. Never use Quimper site values for Casa; model shadows wait for calibrated north. |
| Same-block context | Metered local Street View MCP plus cited source records and reviewed adjacency trace | Target 4–5 useful image views per house; stop at 10 MCP image calls per research task, notify the user and request authorization before further images. Keep images internal. |

Dependencies must be pinned in workspace/requirements lock files and tested, not merely mentioned in docs. Licensing/security review is a gate. Do not install a proprietary DWG SDK or change deployment licensing without recording its terms and runtime prerequisite.

## Release and engineering gates

1. `pnpm check` — lint, typecheck, unit/integration tests and build, including policy regressions that prohibit source hierarchy drift and loss of the solar workspaces.
2. `pnpm architecture:readiness` — prints all mandatory capabilities and blocks any attempt to mark an absent implementation as supported.
3. `pnpm architecture:release-gate` — must pass before release; fails while any required row is not implemented or a tool/fixture/license gate is absent. A local build can run while overall release remains blocked.
4. `pnpm architecture:test` — Python adapter and interoperability tests; Python dependencies are pinned under `scripts/requirements-architecture.txt`.
5. Blender background validation + visual capture; use Blender MCP for live scene inspection/render only when the add-on is connected. If disconnected, report MCP as unavailable and don't claim MCP validation.
6. For every room, audit polygon validity/overlap, a modeled access door on its boundary, room-to-room graph connectivity, and a route to a modeled exterior door. Compare printed source area to traced metric area as an explicit finding; never auto-adjust geometry to hide a discrepancy. Synthetic validator tests do not clear Casa's evidence/review gate.
7. For each IFC/DXF/DWG/glTF/OBJ change: round-trip fixtures, schema/units checks, and geometry comparison are mandatory.
8. For each solar change: tests for date/timezone/coordinates/hemisphere; browser test that Casa slider/date/play/season and room-focus controls render and work; light/shadow regression only after openings and north are evidence-calibrated.
9. Before release, pass horizontal, longitudinal and transverse section modes against the same canonical model and verify sectioning never mutates that model.

## How to keep this system honest

- Keep the machine-readable checklist at `scripts/architecture/capabilities.json`. Every row must have `required: true`, a named implementation and tests/gates. `blocked` is an honest state, not an optional feature.
- If a capability is missing, keep the release gate red. Do not remove a gate to make checks green; implement the capability or report the blocker.
- Every user correction updates this workflow, the root constitution, the machine-readable source/requirements, and a regression test in the same task.
- A successful schema parse is not a survey, design approval, IFC certification, DWG round-trip, or regulatory compliance finding.
