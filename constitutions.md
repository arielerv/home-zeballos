# Constitución operativa de T3 Designer / Casa 2071

Esta constitución es obligatoria para agentes, código, datos, render y exportación. Prevalece sobre notas anteriores, heurísticas del modelo, datos de terceros aproximados y decisiones de implementación. Una corrección explícita del usuario actualiza esta fuente y sus pruebas antes de continuar.

## 1. Verdad del proyecto y evidencia

1. **No inventar ni completar por intuición.** No estimar silenciosamente medidas, orientación, norte, límites, alturas, niveles, estructura, estado de vecinos ni cumplimiento normativo. Cada valor geométrico debe tener fuente, procedencia, confianza y unidades.
2. **Jerarquía de evidencia para la casa terminada.** La planta tentativa gobierna el diseño remodelado en la zona que define; no se la rebaja a una simple marca sobre la planta vieja. Fuera de las demoliciones/modificaciones demostradas, se conserva el estado existente solo si planos, fotos de investigación, Street View u otra fuente identifican de forma verificable ese elemento como existente y retenido. Donde el estado retenido y el plano tentativo se contradigan o el alcance no sea legible, preguntar o bloquear esa parte. El Blender anterior es evidencia de estado/modelo previo, no autoridad automática ni resultado terminado; nunca sobrescribirlo.
3. **No fingir calibración.** Los píxeles de una imagen no son metros. Conservar contornos de trazado en coordenadas de imagen hasta que dos o más correspondencias revisadas y una longitud fiable permitan calibrar escala, giro y traslación. Las áreas impresas son restricciones/valores de referencia, no bastan por sí solas para deducir una planta métrica única. Si falta calibración, bloquear la geometría métrica y etiquetar el proyecto como bloqueado, no como opcional ni terminado.
4. **Conservar el original y la meta final.** El modelo final representa una única casa terminada, con estados `retained`, `new` y `modified` por elemento; la planta tentativa dirige lo remodelado y la evidencia existente dirige únicamente lo que se demuestre retenido. Una altura anterior puede reutilizarse solo si la fuente identifica explícitamente la misma parte como no demolida y respalda esa cota; no trasladar alturas por semejanza visual ni desde meshes sin procedencia. No borrar fuentes ni crear una experiencia antes/después.

5. **Validadores obligatorios:** ejecutar schema, geometría/topología, snapping/tolerancias, cotas/áreas contra la fuente, relaciones muro-hueco, solapes/conectividad, procedencia, calibración, niveles y elementos preservados. ## 3. Capacidades obligatorias del producto

Ninguna fila puede degradarse a «opcional». El estado debe ser `implemented`, `in_progress` o `blocked`; no usar «supported» sin pruebas.

- Dibujo/edición 2D arquitectónica, rejilla, snapping y cotas.
- Muros, puertas, ventanas, losas, techos y niveles con parámetros, IDs y procedencia.
- BIM paramétrico y log de operaciones con revisión/undo.
- Importación/exportación IFC, DXF, DWG, glTF/GLB y OBJ con fixtures y round-trip tests.
- Prompt→proyecto limitado a operaciones tipadas validadas; no ejecutar código generado.
- Validación geométrica y normativa con reglas versionadas por jurisdicción/fuente.
- Auditoría obligatoria de puertas, accesibilidad entre ambientes y egreso exterior para cada planta; tres cortes BIM (horizontal, longitudinal y transversal) revisables, no geometría dibujada aparte.
- Estudio solar como ruta visible de Casa y T3, con pruebas y calibración del modelo para sombras.
- Uso de MCP cuando haya un MCP apropiado disponible para consultar/inspeccionar/renderizar; registrar herramienta, salida, fecha y límites. Un MCP no sustituye la evidencia del usuario ni autoriza a inventar geometría. Si no hay MCP apto (por ejemplo, export IFC), usar la librería/adaptador obligatorio y dejar constancia.

## 4. Dependencias y licencias

La matriz exacta y las puertas de build están en [docs/workflows/casa-bim.md](docs/workflows/casa-bim.md). Las librerías de intercambio/edición seleccionadas son dependencias obligatorias de su adaptador, fijadas por lockfile/requirements. Revisión de licencia, fixture real y pruebas de ida/vuelta son gates; no reducirlos a una lista de sugerencias. Un convertidor propietario se declara como requisito del entorno y nunca se atribuye a una dependencia open source.

## 5. Protocolo ante una contradicción o falta de datos

1. Detener solo la operación afectada; no abandonar el resto del trabajo seguro.
2. Mostrar qué fuente contradice a cuál y qué parte puede modelarse sin asumir.
3. Mantener datos pendientes fuera de la geometría y del render final.
4. Pedir una aclaración concreta únicamente cuando ningún camino verificable permita avanzar.
5. Al recibir corrección, actualizar constitución/datos/tests y las vistas afectadas en la misma tarea para que no se repita el error.

## 6. Gates reproducibles

`pnpm check` debe incluir los tests de arquitectura y solar. La validación de proyecto, el reporte de readiness de formatos y las pruebas Blender/IFC/DXF/DWG son pasos requeridos para el release de arquitectura; las limitaciones del entorno local se informan con estado `blocked`, no se falsea un resultado verde. Ver [docs/workflows/casa-bim.md](docs/workflows/casa-bim.md) para comandos y ownership de cada gate.
